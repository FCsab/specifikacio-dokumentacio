The Specification Editor Book

Search: SEARCH

Linear search (keresés) looks for the first index in a range where a condition holds. It also reports whether there is one.

Form: (found,ind)=SEARCH(i=b..e, β(i))
Result: a pair. found is a logical value telling whether any i in b..e satisfies β(i), and ind is the first such i
If nothing is found: found is false, and ind carries no meaning

found must be declared, usually in Aux: (if the task only asks for the index) or in Out: (if the task asks whether there is a match).

Example: the first negative number

In: n∈N, x∈Z[1..n]
Aux: found∈L
Out: ind∈N
Pre: -
Post: (found,ind)=SEARCH(i=1..n, x[i]<0)

n: 5
x: [3, 8, -2, 7, -5]
found: true
ind: 3

n: 3
x: [3, 8, 7]
found: false
ind: 0

Warning

Don’t call the flag exists. You may run into Aux: exists∈L in older material, but exists is a reserved word (the ASCII form of ∃), and the current editor rejects it with incomplite type for exists: undefined is not boolean. Use found, van or talalt.

What is ind when nothing is found?

When found is false, ind has no meaningful value. The postcondition only says something about it when the search succeeds. In practice:

  • The editor’s step list shows the loop index running past the end, so it displays n+1 (for example ind: 4 when n = 3).
  • In test cases, people write either ind: 0 or ind: n+1. Both pass, and so does leaving ind out of the test case.
n: 3
x: [3, 8, 7]
found: false
ind: 4

Making the output depend on the result

Often the task wants something derived from the found element, and only if there is one. What is the name of the first hive whose queen is at least 3 years old? Use an implication. Wrap it in parentheses:

In: n∈N, names∈S[1..n], age∈N[1..n]
Aux: found∈L, ind∈N
Out: name∈S
Pre: -
Post: (found,ind)=SEARCH(i=1..n, age[i]≥3) and
      (found -> name=names[ind])

n: 3
names: [Akac, Bodza, Repce]
age: [1, 3, 4]
found: true
ind: 2
name: Bodza

n: 2
names: [Akac, Hars]
age: [1, 2]
found: false
ind: 1
name: ""

When nothing is found, found -> … is true no matter what name is.

Warning

-> is the weakest operator. Without the parentheses, (found,ind)=SEARCH(…) and found -> name=names[ind] parses as ((found,ind)=SEARCH(…) and found) -> name=…, which is true whenever the search part is wrong, so a test with wrong data can still pass. Always write and (found -> …).

A sentinel value instead of a flag

Some tasks don’t want a logical value. They want a special output, usually −1, when there is no match:

Print the number of the first hive with more than K mites, or −1 if there is none.

Two changes are needed. The output must be Z (−1 isn’t a natural number), and the postcondition must produce the −1 itself:

In: n∈N, k∈N, mites∈N[1..n]
Aux: found∈L, ind∈N
Out: res∈Z
Pre: -
Post: (found,ind)=SEARCH(i=1..n, mites[i]>k) and
      (found -> res=ind) and
      (not found -> res=-1)

n: 5
k: 30
mites: [12, 30, 45, 7, 60]
found: true
ind: 3
res: 3

n: 3
k: 100
mites: [12, 30, 45]
found: false
ind: 1
res: -1

The worked example The overflowing tank uses the same −1 technique, and solves its task without SEARCH as well.

Searching from the back

To find the last matching index, run the search backwards. The trick is to negate the indices: let i run from -n to -1, look at x[-i], and take the result as -ind:

In: n∈N, x∈Z[1..n]
Aux: found∈L
Out: ind∈N
Pre: -
Post: (found,-ind)=SEARCH(i=-n..-1, x[-i]<0)

n: 5
x: [3, -8, 2, -7, 5]
found: true
ind: 4

As i goes −5, −4, …, −1, -i goes 5, 4, …, 1, so the array is scanned from the end. The first hit is at i = -4, which gives -ind = -4, so ind = 4. The general form is (found,-ind)=SEARCH(i=-e..-b, β(-i)).
